What should we call you?

Your agents use this when they talk to you. It stays on this machine, in a file called profile.json that is not in git.

Step 2 of 5

Name your base agent, and give it a face.

This one is always on. It does not hold any of your data - it collects what the other agents produce and keeps one calendar and one mail view up to date. You are going to spend the next half hour telling it what it may and may not reach, so it helps if it has a name.

Pick its face
Step 3 of 5

Who else is working for you?

Each of these is a separate agent with its own folder, its own tools and its own security policy. None of them can see inside another, and your base agent cannot see inside any of them - it only collects what they hand over. Give each one a face so you can tell them apart; each face can only be used once.

Step 4 of 5

Connect the accounts.

These create local dummy accounts for the workshop. Nothing authenticates anywhere, no password is asked for and no request leaves this machine - the names you type here go into the sample mail, repositories and saved threads your agents read, so the data says your handle instead of a placeholder.

Step 5 of 5

Decide what each one is allowed to touch.

These are starting points, not locks. Every one of them is a plain policy file you can edit while the app is running, and the edit lands on that agent's very next action. Nothing here can grant something the Policy tab could not.
